Source notes and release limits

Source review: 11 November 2026. Merged LastDB revision 07516a81a5e9bc8be93a148792e74f448fad5765.

The guide describes 122 parts and 449 connections. This review covers eight commits after 3cc4d263e. Completed reviews cover 1155 commits after October 21. The review follows implementation and surrounding callers, including vendored LastStore.

Retired multiwriter paths and the remaining Shares

The old dedicated shared homes, portable journals, peer replay, writer rejoin, shared snapshot commands, and v1 shared-storage client are removed. Registered Share publication, invitations, verified recipient copies, and contributor submissions remain. They use separate personal-format homes and the V2 path. They are not replacements for opening an old dedicated shared home.

Replacement writes now supply the full record. Naming an older schema definition no longer preserves omitted fields. Contributor grants still check the exact declaration and allowed action before the publisher performs a normal conditional write.

Opening a home refuses old dedicated shared markers, a disk-private directory, or known portable-journal and delete-age keys. The briefly added automatic cleanup was reverted before this review completed. Startup neither replays nor removes those entries. There is no automatic migration. This review did not open or change a primary home.

The remaining changes consolidate storage, memory, query, expiry, backup, and node modules. Source links follow those moves. LastStore reuses bounded decoders for ordinary reads without changing the publication order. The diagram retains its four-step Disk view and six service groups.

Source: Retired-home admission · Personal-home admission · Contributor validation · Registered Share copies · Manifest decoding

Smaller service surface

The saved app-change feed, its socket route, and the SDK changes() method are removed. Native writes still save their records before acknowledgment. Optional Search delivery remains a separate action after disk publication; it is not a saved app-change feed.

The stopped-home search-rebuild command is removed. Search delivery still stops when its queue reaches the byte or file limit, or when a rebuild marker is present. Existing batches remain. This source no longer provides that built-in command to repair the search index.

Storage inventory now reports live record counts and bytes by schema. The full physical inventory route and descriptive-name claim retirement are removed. Explicit disk cleanup, the deletion ledger, schema expiry, and backfill remain. Request workers retain their bounds and deferred write replies; their queue-wait timing hook is removed.

The preceding review covered a separate consolidation of small source modules. Record ownership, the 64 KiB record cap, the 256 MiB decoded-record warm-set target, conditional writes, typed key order, save-before-ack, and deletion rules remain. That earlier pair of commits left cloud activation, the backup protocol, and vendored LastStore unchanged. The guide links to the current source locations and keeps six service groups, now with 30 parts.

Source: Socket routes · SDK · Native commit · Search delivery and pause marker · Owner commands · Schema names

Format 15: derived lookup keys and two encryption layers

New homes use format 15. Only that format opens or restores. Personal backup profile 14 identifies it. The old shared marker and profile 15 are refused. A format 14 home needs its matching program; changing its marker is not a conversion.

Each primary or alternate key space derives its hash-protection key from the home content key and key-space identity using HKDF-SHA256. The schema supplies typed range order. Stored field-key bundles, their wrapping key path, and the extra ENB: wrapper around file entries are removed. Files still have content encryption and local run-block encryption. The old device-private shared home and its cross-home journal are removed.

Source: Format and profiles · Lookup-key derivation · File encryption · Run keys and layout

Records, memory, and keyed reads

A schema owns complete records with independent primary and alternate addresses. Replacement requires the current revision and the complete new payload. Canonical field reuse shares definitions, not record values. The 64 KiB record cap and ordinary flush-before-ack contract remain.

The warm set retains decoded records and their keys, metadata, and file markers. Its default target is 256 MiB; held records can keep it above that target. Schema definitions use a separate cache. Prepared native writes retain their 512 MiB allowance. The process-memory governor, deferred-memory accounting, allocator tuning, and extra typed-definition warm cache are removed. These remaining limits are not a process-wide memory cap.

Queries now require exact keys, batches of keys, or a range under one hash. Whole-schema record pages, samples, WHERE-style field conditions, field sorting, and range-only selectors are removed. Ascending keyed cursors remain; descending keyed reads use offsets. Owner key listing and internal maintenance enumeration remain separate from query results.

Source: Whole records · Warm-set accounting · Resource bounds · Keyed query rules · Owner key listing

Disk, flush, and deletion

One native request privately prepares its complete change. A bounded queue can combine arriving requests. The caller waits for the durable run commit and clean memory publication before success; there is no collection timer. The removal of timing receipts does not remove these waits.

LastStore still writes a new run and stages CURRENT before publication. Both prerequisites must succeed. CURRENT is renamed and its directory synchronized before the new root becomes current. Ordinary file additions precede record updates, and file deletions follow them. Saved recovery work still handles interrupted file deletion.

Compaction, space reservation, held read roots, and poisoned-lock refusals remain. Detailed physical-file diagnostics and read/commit timing receipts are removed. The remaining physical diagnostic totals allocated bytes in the native directories. The backup key-head and decoded-block reuse cache is also removed; bounded authenticated streaming remains.

Source: Native request completion · Commit and publication · Run and CURRENT prerequisites · Durable publication · Bounded streaming · Current file diagnostic

Expiry belongs to its schema

Retention policies and tracking now use the schema name directly. Cross-name retention anchors and alias chains are removed. Manifest retention requires the declaring app to own the schema; an operator override can retain the manifest policy underneath it. Shortening a manifest TTL still requires explicit confirmation.

The expiry worker runs in its own periodic task. It completes a pass and waits 60 seconds by default, with a separate interval setting. It no longer depends on health sampling or its retry telemetry. Small conditional deletion pages, keyed age discovery, and explicit backfill remain. The old shared-journal binding and its TTL restrictions are removed.

Source: Manifest and operator policies · Schema-owned tracking · Periodic expiry · Keyed expiry discovery

Backup and the narrower restore checks

LastDB owns retention and backup correctness. ExeMem checks account and payment eligibility, routes cloud bytes, and performs cleanup under LastDB’s instructions. It does not interpret database contents or decide independently which backup data is obsolete.

Personal backup retains record runs and uploads stored blob versions separately. Restore creates an empty blob home; later attachment requests fetch and verify their selected version. Registered Share publications refuse ordinary blob attachments; Files sharing stores chunks as records. Snapshot cleanup, automatic policies, exact accepted change chains, and cloud admission remain. The stopped-home backup command and its final snapshot procedure are removed; captures use a running daemon.

Restore still checks exact captured files and roots, supported format markers, replay-floor and author markers, and the account content-key proof. The full logical walk of schemas, records, alternate keys, deletion stamps, inline files, and blob markers is removed. The admission function now reports zero records checked. A successful restore is not an audit of every record or proof that every attachment is available.

An explicit file read still decrypts the selected bytes and checks their size and hash. Local-reference files remain outside run storage, and their personal cloud upload path is incomplete. A record-only restore cannot establish that those source bytes were backed up.

Source: Restore entry point · Account and marker checks · Captured file binding · Stored blob upload · Attachment reads · Current backup commands

Services and source-only additions

The owner socket and bounded workers remain. Status now reports the build, uptime, worker counters, backup activity, and search-queue state. Request rankings, the minute health sampler, session ledger, alert-check, local-watch route, encrypted query-slice export, and native payment commands are removed. The old derived behind/stale/covered backup health report is removed; detailed backup status still exposes saved policy and job facts.

The cloud client, upload planner, host handlers, socket transport, identity helpers, endpoint profile, environment helper, and storage-policy crates have been folded into their consumers. The diagram describes their roles without treating each source crate as a separate service. Apps & services remains nested in six groups; Disk retains a four-step main path and four detail groups.

The advisory schema service and signed app catalog remain separate. Nine JSON standard-schema declarations now describe social-graph and social records. These declarations are source specifications, not evidence of an installed app or deployed service.

Source: Basic status · Backup status fields · Current socket routes · Cloud client location · Planner location · Standard-schema declarations

Unified log and member-list protocol: not connected

The pure mutation-log libraries now identify writers and acknowledgements by node key and device. Read cursors advance across hidden entries without exposing them. An expired cursor can return a snapshot reset and retained entries. The caller must apply and persist that result before acknowledgement.

Retention is bounded by an available snapshot. Pending contributor submissions survive ordinary trimming until incorporation, explicit rejection, or the 30-day limit. Rejected or expired submissions leave a status record. The in-memory adapter and sync step remain unconnected to the node; there is no durable cloud adapter or new runtime recovery qualification. The feature flag is removed. An interim library policy recognizes lastdb-files and social as shareable namespaces; it does not change the current registered Share commands.

New Share member-list and node-read wire types validate shapes and produce signing digests. They perform no I/O or signature verification themselves, and no running-node caller uses them in this revision. They do not replace the existing invitation, guest-read permission, or contributor-grant path. Existing contributor limits remain.

Source: Cursor and reset behavior · Retention and pending submissions · Apply before acknowledgement · Unconnected library boundary · Member-list protocol boundary

Recovery evidence remains version-specific

Ordinary authenticated restore is enabled in source. The earlier PROD recovery run used revision ebd09268f8d151fb6cc382d8b1f9ac2c82e3420d and format 14, before separate blob paths. It recovered generated records, changes, a deletion, and file bytes across clean restarts. The later DEV recovery run used 4132e14aa5430a9bde5676912f7d6d3acc4c47b9 and checked restored-device sign-in, current-file download, and released-version refusal.

Neither historical result qualifies format 15. This review does not claim a new PROD result, deployed service change, stable release, or primary upgrade. Stable release and signed app publication retain their own CI gates. Guide publication changes only the website.
